xv6简介

1.简介

xv6是基于riscv指令集上的类unix操作系统,通过qemu虚拟机模拟riscv环境来启动。
麻雀虽小五脏俱全,xv6包括了系统调用,页表,陷入中断,并发以及文件系统几个部分。虽然一些优化算法及其简单(甚至几乎没有优化),但足够对操作系统进行一个全面的了解。

首先简单了解一下unix系统的一些基础知识,以了解这类系统的一个设计思想,例如文件抽象等,后续会继续深入了解

2.文件对资源的抽象

fork()

函数执行时，子进程立刻完整的复制一份父进程的所有资源，并继续从原位置（无需重新）执行

Unix每个打开的文件都有应该文件描述符fd。xv6内核为每一个进程单独维护一个以文件描述符为索引的表，因此每个进程 都有一个从0开始的文件描述符私有空间
对于每个进程来说，0标准输入,1标准输出,2标准错误
进程并不关心输入输出实际指向的是哪里，只知道从0接收数据，1输出

子进程被创建后调用fork返回0，进入if第一个分支，首先关闭标准输出close(1)
打开文件output.txt，用只写(如果没有则创建这个文件)，此时output.txt得到的文件描述符就是1(open() 总是返回最小的可用文件描述符)，也就占据了原来是标准输出的位置（屏幕）

父进程等待子进程结束,不管其返回状态(null的意思)

如果两个文件描述符是通过一系列的fork和dup(复制一个文件描述符,例如第一个进程调用dup(0)就是把文件描述符1也分配给0所指的文件)调用从同一个原始文件描述符衍生出 来的，那么这两个文件描述符共享一个偏移量。否则，文件描述符不共享偏移量，即使它们 是由同一个文件的打开调用产生的。
也就是只有dup和fork可以共享文件偏移量，其他都不行。理解一下命令
ls existing-file non 11 existing-file > tmp1 2>&1

  1. 只有标准输出重定向（错误信息还在屏幕）
    ls existing-file non-existing-file > tmp1
    结果：tmp1只有”existing-file”，错误信息显示在屏幕上

  2. 标准输出和错误都重定向，但是分开的
    ls existing-file non-existing-file > tmp1 2> tmp2
    结果：正常输出在tmp1，错误信息在tmp2

  3. 标准输出和错误都重定向到同一个文件（你的问题）
    ls existing-file non-existing-file > tmp1 2>&1
    结果：正常输出和错误信息都在tmp1，按顺序排列

2>&1正是通过close(2) fd=dup(1)来实现将标准错误(2)重定向到标准输出(1),&用于确定1是标准输出，而不是一个名为1的文件

pipe


在执行exec之前，close(p[1])先将管道p的写端关闭，防止后续如果没有字节写入，却一直在占用读端,这样wc进程会被自己阻塞(一直等待写入)

文件系统
unix系统用统一的方式处理所有”文件”
大致分为普通文件和设备文件以及目录文件
read/write等系统调用会根据文件类型的不同,路由到不同的处理程序
inode是文件的”身份证”,每个文件的唯一标识，通过

struct stat st;
fstat(fd, &st); // 获取文件描述符对应inode的信息
// st现在包含：
// - type: T_FILE, T_DIR 或 T_DEVICE
// - ino: inode编号（文件的唯一ID）
// - nlink: 有多少个文件名指向这个inode
// - size: 文件大小
// - dev: 所在设备
可以查询到文件的具体信息
link系统调用可以创建一个引用同一个inode的文件(名)，
open(“a”, O_CREATE | O_WRONLY);
link(“a”, “b”);
a,b实际是同一个文件,通过fstat可以得到返回的ino结果相同,nlink连接数为2
unlink删除文件名，如果连接数为0则删除文件

调试工具的安装

在WSL上安装的ubuntu20.04,用git克隆xv6,可以使用vscode连接unbuntu,操作更方便

安装方法

  1. 克隆仓库（约6.65GB，时间较长）
    git clone https://github.com/riscv/riscv-gnu-toolchain
    cd riscv-gnu-toolchain
  2. 安装完整依赖（比单独装gdb多一些包）
    sudo apt install autoconf automake autotools-dev curl python3 libmpc-dev
    libmpfr-dev libgmp-dev gawk build-essential bison flex
    texinfo gperf libtool patchutils bc zlib1g-dev libexpat-dev
    ninja-build git cmake libglib2.0-dev libslirp-dev
  3. 配置并编译Newlib工具链（包含gdb）
    ./configure –prefix=/opt/riscv
    make -j$(nproc)
  4. 加入PATH
    echo ‘export PATH=/opt/riscv/bin:$PATH’ >> ~/.bashrc
    source ~/.bashrc
  5. 验证
    riscv64-unknown-elf-gdb –version

开始调试

用vscode打开两个窗口
一个
make CPUS=1 qemu-gdb以单线程调试模式启动xv6

另一个
gdb-multiarch 启动gdb调试界面
file kernel/kernel加载调试文件
multiarch版本不能调试内核部分,改用下列

riscv64-unknown-elf-gdb kernel/kernel
target remote localhost:26000连接到调试端口
