一、RISC‑V 监督模式控制寄存器

只在 Supervisor 模式 的 Trap 处理中使用
stvec
保存内核 Trap 处理入口地址（trampoline 地址）。
发生 Trap 时，硬件自动跳转到 stvec 指向的位置。
sepc
Trap 发生时，硬件把当前 PC 保存到这里。
sret 指令会将 sepc 写回 PC，实现返回。
内核可修改 sepc，控制返回位置。
scause
硬件写入，记录 Trap 原因编号（系统调用、中断、缺页等）。
sscratch
存放 trapframe 指针，用于快速保存 / 恢复用户上下文。
进入 Trap 时先与通用寄存器交换，避免破坏用户寄存器。
sstatus
SIE 位：控制设备中断使能，清 0 则中断被延迟。
SPP 位：记录 Trap 来自用户态 / 内核态，决定 sret 返回的特权级。

二、Trap 硬件行为（时钟中断除外）

当强制 Trap 发生时，硬件只做 4 件事：
1.若为设备中断，先清 sstatus.SIE，关闭中断。
2.保存 PC → sepc，将 stvec → PC。
3.记录原特权级到 SPP，切换为 Supervisor 模式。
4.填写 scause 说明 Trap 原因。
硬件不做：
不保存通用寄存器
不切换页表
不切换栈
→ 把灵活性留给内核，性能由软件优化。

三、Trampoline（跳板页）核心机制

  1. 为什么需要 Trampoline？
    硬件不自动切换页表。
    stvec 地址必须在用户页表与内核页表中同时有效映射。
    切换页表时，执行地址不能变，否则程序崩溃。
  2. Trampoline 作用
    一段共享映射的代码，用户 / 内核页表映射到同一个物理页。
    负责：保存用户寄存器 → 切换内核页表 → 跳转到内核 C 代码。
    保证切换页表后，PC 不变、执行流不中断。

四、Trapframe（陷阱帧）

一块内存页，用于保存进程上下文。
结构：
前 40 字节：内核数据（内核栈、CPU ID、usertrap 地址、页表根地址）。
后续：保存所有用户寄存器。
每个进程独有，随进程切换而切换。

五、系统调用完整流程（以 ecall 为例）

阶段 1：用户态执行 ecall
用户将系统调用号放入 a7。
执行 ecall，触发 Trap。

阶段 2：硬件动作
切为 Supervisor 模式。
PC → sepc。
PC 跳转到 stvec（trampoline 地址）。
页表不变，仍为用户页表。

阶段 3：Trampoline.S（uservec）
csrrw a0, sscratch, a0：交换 a0 与 sscratch，得到 trapframe 指针。
把所有用户寄存器存入 trapframe。
从 trapframe 加载：
内核栈 → sp
CPU ID → tp
usertrap 地址 → t0
内核页表 → satp
sfence.vma 刷新 TLB。
跳转到 t0（内核 usertrap）。

阶段 4：内核 C 代码（usertrap）
检查 SPP 确认来自用户态。
重新设置 stvec 为内核态 Trap 入口（kernelvec）。
保存 sepc → trapframe.epc（便于软件管理）。
根据 scause 分发处理：
系统调用：syscall()，sepc += 4 指向下一条指令。
时钟中断：处理计时、调度。
缺页异常：分配物理页、建立映射。
处理完调用 usertrapret()。

阶段 5：返回用户态（usertrapret + userret）
关中断，恢复 stvec 为 uservec。
填充 trapframe 内核信息。
设置 sstatus 准备返回用户态。
进入 userret：
切回用户页表。
恢复所有用户寄存器。
sret：sepc → PC，切换回用户态。

六、内存映射与权限位（QEMU info mem）

查看映射：QEMU 控制台 info mem
权限位含义：
r：可读
w：可写
x：可执行
u：用户态可访问
a：已分配
d：已修改（脏位）

七、栈帧与 backtrace（实验）

栈结构
栈从高地址 → 低地址增长。
sp（stack pointer）：栈顶（最低地址）。
fp/s0（frame pointer）：当前栈帧底部（最高地址）。
栈帧布局
fp + 0：当前栈帧基址
fp - 8：返回地址（RA）
fp - 16：上一栈帧指针（prev fp）
backtrace 原理
从当前 fp 开始，循环读取：
打印返回地址。
fp = 上一帧 fp。
直到超出栈页范围。

八、Alarm 实验核心思路

目标
每隔 N 个时钟中断，回调用户指定函数。
test0
单次调用 handler，测试能否触发。
思路：时钟中断时，将 epc 改为 handler 地址。
test1
多次调用 handler，返回后寄存器 / 状态必须完全恢复。
思路：用 alarm_trapframe 保存中断现场，sigreturn 恢复。
test2
禁止重入：handler 执行中不能再被时钟中断打断。
思路：加标志位，handler 执行时置位，返回时清零。

九、关键结论

ecall 不切换页表，页表切换由 trampoline 软件完成。
trampoline 必须共享映射，保证切页表不改变执行地址。
硬件只做最小动作，寄存器 / 栈 / 页表都由内核管理。
trapframe 是进程上下文的 “快照”。
sret 依赖 sepc、sstatus.SPP 完成返回。
