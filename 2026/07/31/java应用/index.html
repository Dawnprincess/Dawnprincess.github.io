枚举(Enumeration)

对于一些常量对象，创建一个类，实际上只有固定的几个对象，可以用枚举。
1.构造器私有化（防止外部调用创建新对象）
2.本类中创建一组对象
3.对外暴露对象（为对象添加public final static 来保证外部可以直接调用该对象）
4.提供get方法，不提供set

类饿汉式实现。（多例饿汉式）

使用enum代替实现
1.class用enum代替
2.对象创建直接写，用,代替，必须写在最前面

对于无参构造器，可以直接用对象名字表示调用生成了一个该名字的对象。

使用enum创建类时，会隐式继承Enum类(java.lang.Enum，可以使用javap反编译看到)，因此也不能继承其他类，但可以实现接口
其中常用方法
1.toString:返回对象名，可以在子类中重写显示属性
2.name:返回对象名，子类不可重写
3.ordinal:返回枚举位次(从0开始)
4.values:以数组形式返回所有枚举对象(包括其属性值)
5.valueOf(“常量名”):可以将String常量名转为对象返回（必须是正确已有的对象，否则报错）
6.compareTo:比较两个枚举常量（的位次）

注解(Annotation，又称元数据Metadata)

用于修饰包、类、方法、属性、构造器、局部变量等数据信息
注解不影响程序逻辑，但可以被编译或运行
主要有三种
@Override:限定某个方法，重写父类方法，仅用于方法。关键在于编译期会去校验是否真的重写


@Target修饰注解的注解（元注解），表示这个注解只修饰方法
@Rentention定义注解的保留策略，仅在原代码阶段生效，编译为.class文件后丢弃，即只在编译期间辅助，运行不用
@interface是定注解类型的关键字

@Deprecated:表示某个程序元素(方法，属性)过时
@SuppressedWarning:抑制编译期警告

元注解
@Rentention:指定注解作用时间，SOURCE(编译期用后丢弃),CLASS(记录在class文件中),RUNTIME(运行该java程序时JVM保留注解)

@Traget:注解元素范围，CONSTRUCTOR, FIELD, LOCAL_VARIABLE,METHOD,PACKAGE...
@Document:将过时注解保留在javadoc文档中
@Inherited:被其修饰的注解将具有继承性，即某个类使用了该被@Inherited修饰的注解，则子类自动也具备该注解

异常

程序执行中发生的不正常情况（语法和程序逻辑错误不属于异常），通过java的异常处理对于不严重的问题可以不影响后续程序的运行。
分为两类
1.Erro错误:Java虚拟机无法解决的严重问题（例如JVM系统内部错误、资源耗尽等），程序会崩溃
2.Exception:其他因变成错误或偶然外在因素导致的一般性问题，可以用针对性代码处理。如空指针访问、试图读取不存在文件，网络连接终端等，主要分为运行时异常和编译时异常。
异常有编译时异常（一般是逻辑错误）和运行时异常。

两种处理方法
try{
可能有异常的部分
}catch(Exception e){
预设的处理异常
}finally{
最终都要执行的部分
}
如果异常发生，则异常后面的部分不会继续执行，而是执行catch部分
finally常用于释放资源部分，也可以省略不写。⭐即便前面有return也要执行完return 表达式里的语句后临时存储起来继续，执行finally
如果预测到多种可能的异常类型，可以用多个catch来分别捕获这些异常，但一定要子类异常写在前，父类在后

throw：如果不对可能的异常做干涉，默认采用抛出(也可以显示表示，写在方法名后)，让调用者处理该异常。最高的调用者就是JVM，会打印异常信息，然后退出程序
子类如果重写父类方法，抛出的异常也必须是父类抛出异常或其子类
thorws的异常必须由调用者处理，编译异常必须由程序员显示进行处理，运行异常程序会自行继续上抛
自定义异常，实际上就是创建一个子类去继承异常（通常继承RuntimeException，可以省去显示调用throw），在调用时throw new 自定义异常即可
注意throw后面是具体的异常对象，放在方法体中。throws是异常类型，放在方法名后

将一个类继承Thread类，并重写run方法，实现业务逻辑，创建对象调用start可以开始执行run方法。

}

互斥锁
1.每个对象都对应一个称为”互斥锁”的标记，这个标记保证任一时刻只有一个线程能访问该对象
2.会导致效率变低
3.同步方法的锁可以是this，也可以是其他对象，例如自定义任意一个对象object，所有对象访问都实际上是去获取object的锁(非静态)
6.同步方法的锁为当前类本身（加到静态方法）

释放锁
1.同步方法、代码块执行结束。
2.同步方法、代码块遇到break,return
3.同步方法、代码块中出现未处理的Error、Exception导致异常
4.同步方法、代码块调用线程对象的wait()，当前线程暂停，释放锁

以下情况不会释放锁
1.在同步方法、代码块中调用Thread.sleep()、Thread.yield暂停当前线程执行
2….其他线程调用该线程的suspend()将该线程挂起

文件

文件的设计思想
1.数据是流动而非静止的，水从外部（文件，网络）流进程序（水缸），水从程序（水缸）流向外部。这意味着不需要一次性把所有数据全部装进内存，而是可以一边写一边处理。
2.装饰器模式——功能叠加，可以按照所需组合不同的功能
如果把数据比作流，那么节点流就是水管本身，它连接数据源（文件、数组、字符串等）到程序，但只能读字节，没有缓冲，效率低。
处理流就是水管上的组装饰器，不直接连接数据源，而是可以套在节点流或其他流上面，增强功能，例如BufferedInputStream，加装蓄水池缓冲，批量处理减少物理读取次数，ObjectInputStream，加装序列化器，将Java对象变为字节流。

3.字节与字符
早期流都是字节InputStream/OutputStream，引入Reader和Writer体系，专门处理字符，例如InputStreamReader和OutputStreamReader

!节点流和处理流

节点流，数据源主要有File,Arrary和Pipe。
1.File用于处理硬盘上持久性存储文件，这是最能理解的部分，那为什么文件处理的数据源还包括了Array和Pipe这些内存数据？答案是接口统一，为了方便对内存中的数据直接调用文件接口进行文件处理操作。（否则需要把内存数据现生成文件，再对生成的文件流调用这些方法）
2.Array主要负责线程内部的数据共享，假设你从网络收到一个byte[] imageData，想要用它生成BufferedImage，但ImageIO只认InputStream

Pipe也是同理，是负责线程之间的数据共享，借助管道，两个线程不需要通过读写文件来共享数据，而是直接通过管道发送和接收。

处理流
1.性能增强类的：
BufferedInputStream/BufferOutputStream，
BufferedWriter/BufferedReader
缓冲区如何增强？通过一次多读，存放到缓冲区来减少后续读取的系统调用次数，从而减少上下文切换的开销。（并没有加快磁盘文件读取速度）

2.类型转换（字节<->字符，字节<->对象）:
InputStreamReader/OutputStreamWriter，
ObjectInputStream/ObjectOutputStream

3.功能增强型的：
DataInputStream/DataOutputStream，读写Java基本数据类型和UTF-8字符串
PrintStream/PrintWriter，格式化输出，将各种类型转为字符串
PushbackInputStream/PushbackReader，回推（unread）已读取的数据，允许偷看下一个字节

BufferedReader类中，有属性Reader，即可以封装一个节点流，该节点可以是任意的，只要是Reader子类
相同的BufferedWriter是Writer的子类即可。
一般BufferedReader属于字符流，对处理文本文件更合适
