java面向对象进阶

类变量（静态变量）

该类的所有对象共享的数据，可以通过对象，也可以通过类来直接访问该变量。
用static修饰。在类加载的时候生成，所有对象存放的引用指向同一块内存（根据JDK版本会存放在不同位置，堆或方法区）。他的访问权限和普通变量一样。

同理的类方法（静态方法），通常将一些通用方法设置为类方法，在类加载的时候生成，这样可以不必创建对象后再调用，直接通过类名调用（普通方法并不可以通过类调用）。

在对象创建时生成，⭐这也意味着类方法通过类只能直接访问静态变量和静态方法，而不能使用普通的变量和方法（还没生成），包括this()，super()这些代指对象。但可以先创建对象再调用（例如创建匿名对象）

main方法

1.main方法由虚拟机调用，所以必须是public，保证可以访问
2.虚拟机调用时不必创建对象，所以必须为static
3.main接受String类型的数组参数，在程序运行时作为传入参数
java 程序 参数1 参数2 …

代码块

代码块可以看做是对构造器的补充（减少重载情况下构造器的冗余）
1.普通代码块可以完全看做构造器的一部分，先于构造器执行，对象创建时执行
2.静态代码块只有在类被加载时执行，例如第一次创建该类对象，子类的对象，调用该类的静态成员

代码块优先顺序和属性初始化一样，执行顺序：静态>普通，其余内部顺序由定义顺序决定

构造器{
super();
普通代码代码块;
…其余
}

整体来看
1.先加载类
1.1加载父类的静态属性初始化和静态代码块
1.2加载子类的静态属性初始化和静态代码块
2.创建对象
1.1加载父类的普通属性初始化和普通代码块，接着构造器
1.2加载子类的普通属性初始化和普通代码块，接着构造器

设计模式（静态方法和属性的经典使用）

前人总结过优化的代码结构，变成风格以及解决问题的思路。类似面对棋局采用不同的棋谱
单例设计模式：即采取一定方法保证整个软件系统，对某个类只有一个对象实例，并且该类只提供一个取得该对象实例的方法
有两种设计，I.饿汉式，II.懒汉式

1.构造器私有化，防止外部直接new
2.类内部创建对象，类加载时就创建
3.对外提供一个静态公共方法获取该对象（只有静态方法可以不通过实例调用方法）

类加载，对象就创建好了，不一定要用就急着创建了，由此得名饿汉式。

1.构造器私有化，防止外部直接new
2.类内部创建对象，在调用时才创建
3.对外提供一个静态公共方法获取该对象（只有静态方法可以不通过实例调用方法）

final

1.修饰类，不能有子类，表示最后一个
2.修饰方法，子类不重写
3.修饰类的某个属性值，不能被修改。特别当final和static同时修饰一个变量，在访问时，可以跳过该类的加载，直接调用该变量。（更快）
4.修饰某个变量，表示常量用_命名，必须有赋值
5.包装类，String，Double，Float，Boolean等都是final类

抽象类

当父类的一些方法不能确定时，可以用abstract来修饰这个方法，为抽象方法，修饰类为抽象类。
抽象类里的方法不一定是抽象方法，但如果有抽象方法，那么该类必须是抽象类。
一个类如果要继承抽象类，那么它必须实现抽象类里的抽象方法，或者它也声明为抽象类。

由此抽象类最终必须要被重写一部分，所以不能用static，final，private来修饰。

接口

接口给出一些没有实现的方法(JDK8后可以有实现)，后续当某个类使用时，必须把这些方法具体实现。
interface 接口名{
//属性（实际上是⭐public static final 属性，这样才能保证接口的属性值为公开常量）
//方法(1.抽象方法 2.默认实现方法 3.静态方法)
}
接口的细节
1.接口不能被实例化
2.接口中所有方法都是public(JDK9后有private)，接口中抽象方法不需要用abstract修饰
3.普通类实现接口必须将接口方法全部实现，抽象类实现接口可以不用全部实现
4.类可以同时实现多个接口
5.接口只能是默认和Public（和抽象类一样）

内部类

被嵌套在类中的类为内部类，类的五部分：属性，方法，构造器，代码块和内部类

1.局部内部类：定义在外部类的局部位置，通常在方法。
I.可以访问外部类的所有成员
II.不能添加访问修饰符（public），但可以final修饰
III.相当于一个局部变量，作用域只能在定义它的方法内（或者代码块内），相应的，调用也只能在这个作用域调用
IV.用外部类名称.this.变量名。来访问外部类的属性

2.⭐匿名内部类
需求场景：当频繁的想创建一个新的类去继承旧类或接口，并调用一次里面的方法，后续不会再用。可以采用匿名内部类的方式，来将创建类和创建对象合并起来，并且不用想名字。
